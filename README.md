# Фильтр подписки под Gemini

Шаблон, который оставляет в подписке только те серверы, где Gemini **реально открывается**. Каждый адрес проверяется по-настоящему: поднимается xray, через его SOCKS делается запрос к Gemini, и сервер отсеивается, если Gemini закрыт по региону или сервер не отвечает.

В репозитории нет ни токенов, ни данных подписки — только код. Чтобы запустить, нужно подставить свои значения.

---

## Что внутри

| Файл | Зачем |
|---|---|
| `filter_servers.py` | Основной скрипт: забирает подписку, проверяет серверы, публикует результат |
| `config.example.json` | Шаблон конфига — скопируй в `config.json` и заполни |
| `gemini_countries.json` | 242 страны, где Gemini доступен |
| `refresh_countries.py` | Обновляет список стран |
| `pages/workgemini_path.js` | Функция Cloudflare Pages: отдаёт подписку в нужном формате |
| `pages/gemini.js` | Вход по паролю, запоминание IP |
| `pages/gemini_index.html` | Страница со сводкой и списком серверов |
| `deploy.py` | Раскладывает файлы сайта в репозиторий Pages |
| `install_autostart.ps1` | Ставит запуск проверки в автозагрузку Windows |

---

## Как это работает

Порядок проверки выбран не случайно. Gemini **не отдаёт признак региональной блокировки в разметке**: русский и немецкий выходы возвращают одинаковый `200 OK` на `/app`, `/chat`, `robots.txt`. По вёрстке отличить нельзя. Поэтому сначала определяется страна выхода, а уже потом подтверждается, что `/app` отвечает `200`.

Страна берётся через SOCKS самого проверяемого сервера, поэтому в подписку попадает реальный выход, а не заявленная метка. Метки в подписях врут регулярно: сервер с названием «Россия» может выходить в Нидерландах.

Чистка имён: из подписей убираются доменные подсказки в скобках, метки `NEW`, служебные пиктограммы, рекламные хвосты. Затем имена собираются заново в виде `Провайдер ⏳осталось | 🇩🇪 Страна 3`, а нумерация расставляется по порядку — иначе после удаления подсказок половина имён совпадает. Сортировка — по странам, потом по провайдеру.

## Форматы выдачи

Функция на `/workgemini` сама подбирает формат по User-Agent:

| Клиент | Формат | Зачем так |
|---|---|---|
| Happ | JSON-массив конфигов | Happ не понимает Clash YAML — нужен его собственный формат |
| Clash / Mihomo / Stash | Clash YAML | Им нужен YAML с `proxy-groups` |
| v2rayNG и прочие | base64 со ссылками `vless://` | Самый универсальный вид |

Формат можно задать и явно: `?format=happ`, `?format=clash`, `?format=base64`, `?format=links`.

Для Happ отдаётся массив: первый элемент — «Автовыбор» со всеми серверами и балансировщиком `leastPing`, дальше по элементу на сервер.

---

## Почему данные лежат в KV, а не в репозитории

Cloudflare Pages отдаёт **любой** файл из репозитория как статику по прямой ссылке. Пока данные подписки лежали файлами, `workgemini.txt` можно было скачать без пароля — пароль был только украшением. Поэтому подписка и сводка лежат в KV, а функция отдаёт их по паролю.

## Установка

1. Скопируй `config.example.json` в `config.json` и заполни: токен подписки, пути к xray, id аккаунта Cloudflare и id пространства KV, адрес своего сайта и репозиторий.
2. Токен Cloudflare положи в переменную окружения `CF_TOKEN`, **не** в конфиг.
3. Пароль задай переменной `PASSWORD` в настройках Pages-проекта. В коде его быть не должно: репозиторий может стать публичным, а пароль в коде — это пароль на видном месте.
4. Залей файлы сайта: `python deploy.py --repo твой-аккаунт/твой-репозиторий`.
5. Первый прогон: `powershell -ExecutionPolicy Bypass -File .\run_now.ps1 -SkipTun -Console`.
6. Автозапуск: `powershell -ExecutionPolicy Bypass -File .\install_autostart.ps1`.

Подробности по каждому шагу — в комментариях внутри самих файлов.

---

## Требования

- Windows, Python 3.10+
- `xray.exe` (или sing-box) — проверка идёт через него
- `gh` CLI авторизован, если используешь `deploy.py`
- Cloudflare: проект Pages, домен, пространство KV, токен с правом записи в KV

На macOS и Linux скрипт потребует правок: он рассчитан на Windows (`CREATE_NO_WINDOW`, разворачивание xray, автозагрузка через Startup).

---

## Если серверы не проверяются

`--skip-tun` в `run_now.ps1` и в `filter_servers.py` снимает проверку того, что не поднят VPN. В `config.json` за это отвечает `check.skip_tun_check`.

Если оставить VPN включённым, весь трафик проверки пойдёт через него вместо проверяемого сервера, и замеры будут бессмысленны: страна выхода покажет страну VPN, а не сервера. Если умеешь добавить `xray.exe` и `curl.exe` в список «идти напрямую» в своём клиенте — тогда проверка заработает и с включённым VPN.
