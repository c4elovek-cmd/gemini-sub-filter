# Фильтр подписки под Gemini

Шаблон, который оставляет в подписке только те серверы, где Gemini **реально открывается**. Каждый адрес проверяется по-настоящему: поднимается xray, через его SOCKS делается запрос к Gemini, и сервер отсеивается, если Gemini закрыт по региону или сервер не отвечает.

В репозитории нет ни токенов, ни данных подписки — только код. Чтобы запустить, нужно подставить свои значения.

---

## Что внутри

| Файл | Зачем |
|---|---|
| `filter_servers.py` | Основной скрипт: забирает подписку, проверяет серверы, публикует результат |
| `config.example.json` | Шаблон конфига — скопируй в `config.json` и заполни |
| `gemini_countries.json` | 242 страны, где Gemini доступен |
| `refresh_countries.py` | Обновляет список стран |
| `pages/workgemini_path.js` | Функция Cloudflare Pages: отдаёт подписку в нужном формате |
| `pages/gemini.js` | Вход по паролю, запоминание IP |
| `pages/gemini_index.html` | Страница со сводкой и списком серверов |
| `deploy.py` | Раскладывает файлы сайта в репозиторий Pages |
| `install_autostart.ps1` | Ставит запуск проверки в автозагрузку Windows |

## Как это работает

Порядок шагов выбран из-за лимитов геосервисов, а не из логики.

Региональную блокировку в разметке не видно: русский и немецкий выходы отдают одинаковый `200 OK` на `/app`, `/chat` и `robots.txt`. Единственный способ её увидеть — страна выхода. Но бесплатные геосервисы отдают десятки запросов в минуту, и на 321 адресе половина запросов отваливалась: в прошлом прогоне 151 сервер выпал на гео, не спросив у Gemini вообще ничего.

Поэтому шагов два, и они именно в таком порядке:

1. **Сначала Gemini.** Один запрос на сервер, и сразу отсекаются мёртвые.
2. **Потом страна выхода** — только у тех, кто ответил `200`. Таких около сотни, лимит перестаёт мешать, и страна определяется почти всегда.

Если сервер ответил `200`, но страна не определилась, он остаётся в подписке с пометкой «страна не определена, но Gemini ответил». Рабочий сервер жалеть из-за лимита стороннего сервиса — хуже, чем одна непроверенная страна, и такие видно в отчёте отдельной строкой.

Чистка имён: из подписей убираются доменные подсказки в скобках, метки `NEW`, служебные пиктограммы, рекламные хвосты. Затем имена собираются заново в виде `Провайдер ⏳осталось | 🇩🇪 Страна 3`, а нумерация расставляется по порядку — иначе после удаления подсказок половина имён совпадает. Сортировка — по странам, потом по провайдеру.

## Форматы выдачи

Функция на `/workgemini` сама подбирает формат по User-Agent:

| Клиент | Формат | Зачем так |
|---|---|---|
| Happ | JSON-массив конфигов | Happ не понимает Clash YAML — нужен его собственный формат |
| Clash / Mihomo / Stash | Clash YAML | Им нужен YAML с `proxy-groups` |
| v2rayNG и прочие | base64 со ссылками `vless://` | Самый универсальный вид |

Формат можно задать и явно: `?format=happ`, `?format=clash`, `?format=base64`, `?format=links`.

Для Happ отдаётся массив: первый элемент — «Автовыбор» со всеми серверами и балансировщиком `leastPing`, дальше по элементу на сервер.

---

## Почему данные лежат в KV, а не в репозитории

Cloudflare Pages отдаёт **любой** файл из репозитория как статику по прямой ссылке. Пока данные подписки лежали файлами, `workgemini.txt` можно было скачать без пароля — пароль был только украшением. Поэтому подписка и сводка лежат в KV, а функция отдаёт их по паролю.

## Как защищена выдача

| Слой | Что делает |
|---|---|
| Пароль | Живёт только в переменной окружения Pages, в коде его нет |
| Запомненный IP | Вводишь пароль на странице — адрес запоминается на 14 дней, дальше обычная ссылка работает сама |
| Журнал доступа | В KV пишется, кто и когда забрал подписку: адрес, клиент, формат, размер |
| Ограничение попыток | 10 неудачных попыток с одного адреса — потом 10 минут отказа |

Что стоит знать:

- **Вводи пароль при выключенном VPN.** Иначе запомнится не твой адрес, а общий выход VPN-сервера, и подписку сможет забрать кто угодно, кто выходит через тот же сервер.
- **14 дней — не вечность.** Общий Wi-Fi, гостиница, NAT оператора — с точки зрения сервера это один адрес. Срок специально короткий.
- **Журнал — это единственный способ заметить утечку.** Сам посмотри: `GET` ключа `wg_accesslog` в KV. Если там чужие адреса — ссылка утекла, меняй имена файлов зеркала и пароль.

## Зеркало на GitHub

Нужно там, где основной адрес не доходит: имя домена местами фильтруется по HTTPS, и без VPN подписка не обновляется.

Подписка дублируется в секретный gist, а имя каждого файла — случайный токен из 40 символов.

Чего зеркало **не** делает: не проверяет пароль. Статика не умеет авторизовывать, поэтому защита держится только на невозможности угадать ссылку. Это запасной путь, а не основной.

Форматы берутся у сайта, а не собираются заново: если построить их в Python, через месяц две реализации разойдутся и зеркало начнёт отдавать не то же, что основная ссылка. Для служебной выкачки сайт сжимает ответ (`?gz=1`) — без этого большие ответы через домашний канал не доезжают.

Обновляется зеркало вместе с подпиской, автоматически. Учти: CDN GitHub кэширует файл примерно на 5 минут, так что сразу после публикации может отдаться предыдущая версия — для подписки это несущественно.

## Установка

1. Скопируй `config.example.json` в `config.json` и заполни: токен подписки, пути к xray, id аккаунта Cloudflare и id пространства KV, адрес своего сайта и репозиторий.
2. Токен Cloudflare положи в переменную окружения `CF_TOKEN`, **не** в конфиг.
3. Пароль задай переменной `PASSWORD` в настройках Pages-проекта. В коде его быть не должно: репозиторий может стать публичным, а пароль в коде — это пароль на видном месте.
4. Залей файлы сайта: `python deploy.py --repo твой-аккаунт/твой-репозиторий`.
5. Первый прогон: `powershell -ExecutionPolicy Bypass -File .\run_now.ps1 -SkipTun -Console`.
6. Автозапуск: `powershell -ExecutionPolicy Bypass -File .\install_autostart.ps1`.

Подробности по каждому шагу — в комментариях внутри самих файлов.

## Требования

- Windows, Python 3.10+
- `xray.exe` (или sing-box) — проверка идёт через него
- `gh` CLI авторизован, если используешь `deploy.py`
- Cloudflare: проект Pages, домен, пространство KV, токен с правом записи в KV

На macOS и Linux скрипт потребует правок: он рассчитан на Windows (`CREATE_NO_WINDOW`, разворачивание xray, автозагрузка через Startup).

## Если серверы не проверяются

`--skip-tun` в `run_now.ps1` и в `filter_servers.py` снимает проверку того, что не поднят VPN. В `config.json` за это отвечает `check.skip_tun_check`.

Проверка ходит через xray и curl. Если в своём клиенте есть список приложений, которым надо идти напрямую, добавь туда `xray.exe` и `curl.exe` — тогда весь замер пойдёт мимо туннеля, и **проверка будет работать при включённом VPN**. Это проверено: с поднятым туннелем выходы проверяемых серверов остаются их собственными, а не адресом машины.

Проверить, что обход действительно работает, можно так: запусти `python filter_servers.py --limit 5 --no-publish --skip-tun`, открой `out/report.json` и сравни поле `exit_ip` с адресом машины. Если ни один не совпал — обход есть.
