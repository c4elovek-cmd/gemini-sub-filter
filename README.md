# Фильтр подписки ShareSub по Gemini

Берёт подписку ShareSub, проверяет каждый сервер на реальную доступность
Google Gemini и выкладывает результат на `https://c4elovek.online/workgemini`.
Запускается автоматически при входе в компьютер.

Сайт — Cloudflare Pages, исходники в приватном репозитории
`c4elovek-cmd/BiographyWebsite`.

---

## Как это устроено

```
ПК (вход в систему)
  └─ run_hidden.vbs → run_now.ps1 → filter_servers.py
        ├─ тянет подписку ShareSub (~470 ссылок)
        ├─ оставляет по одной на уникальный host:port (~327)
        ├─ для каждого поднимает локальный SOCKS5 через xray
        ├─ определяет страну выхода, сверяет со списком стран Gemini
        ├─ подтверждает, что gemini.google.com/app отвечает 200
        └─ пишет рабочие серверы в Cloudflare KV

c4elovek.online/workgemini  (Pages Function)
  ├─ проверяет пароль или запомненный IP
  ├─ отдаёт формат по User-Agent: Happ — JSON, Clash — YAML, остальным —
  │  обычные ссылки vless://, trojan:// и прочие
  └─ добавляет заголовки, из которых клиент рисует карточку подписки
```

## Зеркала

Карточку подписки клиент собирает из HTTP-заголовков ответа: `Subscription-Userinfo`
даёт трафик и срок, `Content-Disposition` и `Profile-Title` — название, `Announce` —
описание. Поэтому зеркало на обычном статическом хостинге карточки не покажет:
файл отдаётся как есть, и заголовков у него нет.

Отсюда два зеркала с разным смыслом:

| Зеркало | Хостинг | Карточка | Зачем |
|---------|---------|----------|-------|
| `mirror.files` — gist | GitHub | нет | Самый простой запасной путь, без облака |
| `mirror.yandex` — Yandex Cloud | `functions.yandexcloud.net` | **есть** | Полная карточка на другом имени домена |

Зачем второе. Если основной адрес недоступен из-за фильтрации имени в сети
(ТСПУ смотрит на SNI в HTTPS), зеркало на другом имени домена фильтрацию не
задевает — но только если этот хост отдаёт заголовки. `workers.dev` и
`pages.dev` для этого не годились: они в России заблокированы. Yandex Cloud
работает внутри страны, поэтому доступен по определению, а данные лежат в
Object Storage и отдаются функцией — она формирует все те же заголовки.

Данные функция берёт из бакета, а не с основного адреса: запрос изнутри России
шёл бы через ту же фильтрацию и мог бы не дойти. В бакет их кладёт
`filter_servers.py` при каждой публикации, вместе с обновлением gist.

Защита у обоих зеркал одна — секретность ссылки: имя gist или токен в пути
известны только вам. Клиент подписки не умеет авторизовываться, поэтому пароля
на зеркале быть не может.

### Развернуть зеркало в Yandex Cloud

1. В консоли Yandex Cloud создайте сервисный аккаунт и скачайте файл ключа (JSON).
2. Впишите в `config.json` → `mirror.yandex`: `service_account_key` (путь к файлу),
   `service_account` и `folder_id`.
3. `python deploy_yandex.py` — создаст бакет, разложит данные и опубликует функцию.

Дальше скрипт сам покажет адрес и проверит заголовки. Данные обновляются запуском
`filter_servers.py` — отдельно ничего делать не нужно.

## Почему проверка такая

HTML страницы Gemini **одинаков для любой страны**: и российский, и немецкий
выход отдавали одинаковые `200 OK` с одинаковой разметкой. Блокировка по
региону происходит после авторизации и в HTML не видна. Проверено на
`/`, `/app`, `/chat`, `robots.txt`, `sitemap.xml`, `StreamGenerate`,
`generativelanguage.googleapis.com` — разницы нет.

Поэтому порядок другой: сначала страна выхода по официальному списку Google
(242 страны), и только потом подтверждение, что `/app` реально отвечает.
Иначе рабочие российские серверы проходили бы как исправные.

## Что отсеивается

| Причина                              | Что означает                       |
|--------------------------------------|-----------------------------------|
| `страна XX — Gemini недоступен`       | сервер жив, но регион закрыт       |
| `Gemini ответил HTTP 0`               | туннель не поднялся                |
| `HTTP 429`                           | Google троттлит, пробуем ещё раз  |
| `не удалось определить страну выхода` | сервер мёртв или geo-сервис не отвечает |

Метки в подписке врут: сервер с названием «🇷🇺 Россия» может выходить
с Нидерландов. Доверяем только реальному IP выхода.

## Доступ

Пароль вводится один раз на `https://c4elovek.online/gemini/` — после этого
IP запоминается в KV на 90 дней, и обычная ссылка `/workgemini` работает.

Пароль можно передать и напрямую:

| Способ                | Ссылка                        | Кто понимает          |
|-----------------------|-------------------------------|-----------------------|
| в пути                | `/workgemini/<пароль>`        | все VPN-клиенты       |
| в запросе             | `/workgemini?key=<пароль>`    | все                   |
| Basic Auth            | окно ввода в браузере         | только браузер        |

Если `/workgemini` открыть в браузере, он перенаправит на страницу
`/gemini/` — VPN-клиенты при этом получают подписку как обычно: они
различаются по `User-Agent` и по `Accept` (клиенты шлют «звёздочку» или
ничего, браузер — `text/html`). Явный `?format=` от редиректа не отключает.

Пароль лежит в переменной окружения Pages (`PASSWORD`), не в коде.
Репозиторий приватный, но и в коде пароля быть не должно.

Защита от подбора: 10 попыток с одного IP за 10 минут, потом 429.

## Почему данные в KV, а не в репозитории

Cloudflare Pages раздаёт **всё**, что лежит в репозитории, как обычную статику
по прямому пути. Когда подписка лежала файлом `workgemini.txt`, её мог скачать
кто угодно без пароля — `functions` перехватывает только `/workgemini`,
а `/workgemini.txt` никто не трогал.

Сейчас файлов с данными в репозитории нет, всё лежит в KV и отдаётся только
после проверки пароля.

## Важно: TUN должен быть выключен

Если включён TUN-режим VPN (Happ, v2rayN), весь трафик уже идёт через текущий
сервер клиента, и проверять другие серверы бессмысленно — результат будет
одинаковым для всех. Скрипт это **детектит и откажется работать**, а не
напишет мусор в подписку.

Локальные прокси (v2rayN на 10808/10809) не мешают: скрипт ходит через
явный `--socks5-hostname`.

Обойти: `--skip-tun` или `check.skip_tun_check: true`.

## Запуск

```powershell
# разовая проверка в консоли
powershell -ExecutionPolicy Bypass -File .\run_now.ps1 -SkipTun -Console

# только проверка, без публикации
powershell -ExecutionPolicy Bypass -File .\run_now.ps1 -NoPublish -SkipTun -Console -Limit 20

# опубликовать прошлый результат, не проверяя заново
python filter_servers.py --publish-only

# тихо, как при автозапуске
wscript .\run_hidden.vbs
```

Результаты прогона: `out/report.json` (по каждому серверу страна, IP, скорость,
причина отказа) и `out/workgemini.txt`.

## Автозапуск

```powershell
powershell -ExecutionPolicy Bypass -File .\install_autostart.ps1
```

Создаёт задачу планировщика с двумя срабатываниями: через 2 минуты после входа
в систему и далее раз в час (`-RepeatMinutes`, по умолчанию 60). Повторный запуск
при ещё не завершившемся не запускается — `MultipleInstances=IgnoreNew`, иначе
проверки накладывались бы друг на друга.

Снять:

```powershell
powershell -ExecutionPolicy Bypass -File .\install_autostart.ps1 -Uninstall
```

Окон не появляется: задача запускается скрыто, `run_hidden.vbs` стартует
PowerShell через `WScript.Shell.Run(..., 0, True)` — последний параметр
обязателен, без него скрипт завершится, не дождавшись работы, а `filter_servers.py`
передаёт `CREATE_NO_WINDOW` каждому дочернему процессу (`curl`, `xray`, `powershell`).

## Настройки (`config.json`)

| Параметр                       | Смысл                                        |
|--------------------------------|----------------------------------------------|
| `subscription.hwid`            | Идентификатор устройства, тот же, что в Happ  |
| `subscription.user_agent`      | `v2rayNG/1.11.1` — чтобы пришли сырые ссылки |
| `check.concurrency`            | Сколько серверов проверять разом (8)          |
| `check.timeout_seconds`        | Таймаут одного запроса (15)                  |
| `check.max_ping_ms`            | Порог пинга в мс, выше — отсекается (1000)      |
| `publish.kv_namespace_id`      | namespace Worker KV с подпиской               |
| `publish.cloudflare_account_id`| Account ID Cloudflare                         |
| `mirror.files`                 | Имена файлов в gist: `happ`, `links`, `clash`   |
| `mirror.yandex.*`              | Бакет, функция и ключ сервисного аккаунта      |
| `cores.xray`                   | Путь к xray.exe                               |

Токен Cloudflare нужен с правами **Workers KV Storage: Edit**.
Положить в переменную окружения `CF_TOKEN`.

## Возможные проблемы

**`HTTP 429` много в отчёте** — Google троттлит при быстрых проверках.
Уменьшите `check.concurrency` до 4.

**`страна XX — Gemini недоступен` в отчёте, но не в подписке** — так и должно
быть: это живые серверы в закрытых регионах, они отсеиваются намеренно.

**Список стран устарел** — `python refresh_countries.py`.

**В логах пусто** — смотрите `logs/run-*.log`. Нет файлов — скрипт не
стартовал; проверьте автозапуск.

**Подписка не обновилась** — Cloudflare KV не кэшируется, изменения видны
сразу; если нет, проверьте `GET https://c4elovek.online/workgemini/<пароль>/status`.
